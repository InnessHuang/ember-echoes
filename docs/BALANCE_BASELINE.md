# Task 04A：确定性策略模拟与第一轮平衡基线

## 研究问题与范围

比较四种固定策略在轻型、重型、Boss 三个独立敌人面前的结束状态、行动耗时与生命代价，观察无效/低效行为及策略依赖。仅做基线测量，不改游戏参数、规则或 UI，不实现三战流程、参数扫描或 Python 模拟器。

引擎基线为 Task 03 提交 `8fc910d75ba42387ab34dbcde7df35df0e8c581d`。模拟器位于 `lib/simulation/`，只由现有引擎结算战斗。策略定义在运行前固定，不根据结果调阈值。

## 可证伪的初始假设

- B 的初始重击可能减少相对 A 的胜利行动数和承伤。
- C 的主动蓄能可能以延迟输出换取长期输出收益，但需要承担额外敌方攻击。
- D 的致命威胁响应可能延长存活并改变 B 的失败结果；“存活更久”与“胜利”分开衡量。

以上是实验假设；后文用实际轨迹支持或限定，不视为普遍规律。

## 实验条件与复现

每个场景只在矩阵中记录一次：3 敌人 × 4 策略，共 12 场，无随机数，无胜率统计。每次调用 `createInitialProgress()` 和 `startBattle(enemyId, progress)`，独立初始化生命 100、能量 2/4、所有升级 0；敌人和 Boss 计数重新初始化。任何实验不继承其他实验的状态。

依赖沿用现有锁文件，Node.js 24、项目 TypeScript 5.9.3。仓库根目录运行：

```sh
npm ci
node scripts/run-baseline.mjs
```

脚本使用项目已有 TypeScript 编译器将引擎与模拟模块编译到系统临时目录，再执行；结束删除临时编译产物，不改项目编译/构建配置。只写入以下两份预期分析数据：

- `data/simulation/baseline-results.csv`：24 个汇总字段，12 条数据行。
- `data/simulation/baseline-actions.json`：schema 版本、引擎基线 SHA、完整基础配置快照、上限、指标口径和 12 场完整轨迹（共 63 次已接受行动）。每步包含选择前意图、行动、接受标识、原始前后状态、引擎 effects 和错误原因。

不写时间戳，内容顺序固定。测试将重新计算的基线与已保存 JSON/CSV 对照，避免结果文件与当前实现漂移；重复计算用于验证复现性，不计为新增样本或提高胜率的证据。

## 策略的精确定义

| ID | 决策规则 |
| --- | --- |
| A | 每步都普攻。 |
| B | 能量至少为集中配置中的重击成本时重击，否则普攻；不防御、不蓄能。 |
| C | 当前能量低于当前能量上限时蓄能，否则重击；不防御。上限读取状态，非硬编码为 4。 |
| D | 每步查询引擎当前意图。仅当 `HP - 意图伤害 <= 0` 且 `HP - max(0, 意图伤害 - 当前有效减伤) > 0` 时防御；否则按 B 选择重击或普攻。 |

D 的当前有效减伤由集中配置中的防御基础减伤和已有护甲次数增量计算。本矩阵无升级，数值为 12。该公式仅用于策略对已公布意图的生存判断；实际防御、伤害与能量始终由引擎处理。

D 不预测玩家本次攻击是否会先击杀敌人，不模拟未来回合，也不在“防御仍会死”时继续防御。它是指定的局部响应策略，不是最优策略搜索。其他策略也仅依赖当前状态，不预知结局。

## 指标口径与终止规则

- `playerActions`：引擎接受并执行的玩家行动数，包含终结行动；不用 `turn` 直接替代（引擎 turn 从 1 开始）。四类 actionCount 之和必须等于它。
- `actionAttempts`：完整轨迹条数，包含拒绝或异常的尝试。基础场景没有拒绝，所以与玩家行动数相同。
- `enemyAttacks`：每步引擎实际攻击计数的增量之和；击杀敌人时不增，完全抵消仍增。
- `playerHp`、`enemyHp`：引擎的最终原始生命，可为负；初始 HP、能量、上限和最终能量均另存。
- `totalDamageDealt` / `totalDamageTaken`：有效生命损失。逐步计算 `max(0, beforeHP) - max(0, afterHP)`，不将打到 0 以下的过量伤害计入有效输出或有效生命代价，也不把被防御抵消的伤害记入承伤。
- `rawHpLossDealt` / `rawHpLossTaken`：逐步原始 HP 差，完整保留引擎允许的负生命信息，供核对 overkill。两种口径不混用。比如轻型 A 实际原始 HP 为 42 → -6，原始差 48，有效输出 42；Boss A 玩家为 100 → -4，原始差 104，有效生命损失 100。
- `bossNormalAttacks` / `bossSpecialAttacks`：只从实际执行的 effects.enemyIntent 分类，不把预告计为攻击。非 Boss 场景均为 0。
- 胜负只取引擎 phase。最多执行 200 次玩家行动，若第 200 次结束则保留胜负；若仍 ongoing 则 `timeout`，保留全部轨迹并写原因。不得执行第 201 次。
- 引擎拒绝、策略异常、非法状态或计数异常立即标记 `error`，保留此前有效指标和失败尝试，不重试或换策略。初始状态与策略输入被冻结，防止策略污染实验。
- 基础矩阵没有 timeout 或 error。独立测试用持续防御轻型敌人的策略验证真实引擎下 200 次 timeout；它不属于四种基础策略，也未混入 12 场数据。

## 观察与解释

### 实际观察

1. 轻型：B/D 在 3 次行动胜利、有效承伤 18；A/C 均为 4 次、承伤 27。D 未触发防御，与 B 完全相同。
2. 重型：B/D 为 4 次行动、承伤 39；A 为 5 次、52；C 为 6 次、65。D 仍未触发防御。
3. Boss：A/B/C 均在第 7 次行动失败，实际遭到 5 次普通和 2 次特殊攻击，玩家原始 HP -4。三者有效输出分别为 84/97/75，敌人剩余 36/23/45。
4. Boss D 在第 9 次行动失败，有效输出 110，敌人剩余 10，遭到 6 次普通和 3 次特殊攻击；原始 HP -14。延长存活与提高输出没有转化为胜利。
5. 四种策略在本基线下均未击败 Boss，但只有这四种预定义策略被检验，不能推导“Boss 无解”。

### 由轨迹支持的解释

- 在轻型与重型场景中，B 的初始重击使击杀提前一次，从而少承受一次敌方攻击。数据支持本范围内“使用初始能量的价值”，不证明重击在所有状态都优于其他行动。
- C 固定在未满能量时蓄能，形成“蓄能 → 重击”的循环。轻型与 A 持平，重型比 A 多两次敌方攻击，Boss 有效输出比 A 低。它没有根据剩余敌人生命改用普攻，延迟输出与过量击杀均可在轨迹中观察；这说明该固定策略低效，不等同于“蓄能行动无用”。
- Boss D 的关键轨迹：前 6 次行动后玩家 HP 8、敌人 HP 35、能量 0。第 7/8 次预告均为普通攻击 12，防御可完全抵消，D 连续防御两次并获得能量 2；第 9 次为特殊攻击 22，防御后仍会受到 10，无法保护 HP 8，因此按既定规则改为重击。重击使敌人 HP 35 → 10，随后玩家受到 22，HP 8 → -14。它严格遵守了条件，没有因失败后改阈值。

## 尚未验证的假设与局限

- 未检验“提前防御换能量”、按敌人剩余生命选择终结行动、其他蓄能时机或最优行动序列是否能击败 Boss。
- Boss 本轮无升级、满血独立开战；真实三战流程预期带有升级和生命消耗。当前实验不能代表完整挑战难度，也不能据此直接要求削弱 Boss。
- 没有参数扫描、随机采样、统计置信区间或玩家测试。这是固定策略下的确定性结果，不是胜率或玩家体验结论。
- D 的局部致命判断不包含“玩家先击杀则无反击”的进攻决策优势，可能漏掉其他有效行为；本轮依照指定定义，不修正策略。
- 模拟器的状态合法性检查与 frozen 输入用于尽早报告错误，不是外部存档验证器。无第三方服务、网络或随机依赖。
