## 配置与加成计算约定

基础配置集中在 `data/game-config.ts`，由 `lib/game/engine.ts` 读取。基础配置运行时冻结，升级次数独立保存在进度中；前端不得复制计算。

以已选择锋刃次数 B、蓄能核心次数 C、强化护甲次数 A 表示累计加成（初始均为 0）：

- 普攻伤害 = 基础普攻 12 + 3 × B。
- 重击伤害 = 基础重击 25 + 3 × B，消耗固定为 2。
- 当前能量上限 = 基础上限 4 + C。
- 防御减伤 = 基础减伤 12 + 6 × A。

前两战胜利后各提供三个固定选项，重复选择同一升级的增量累加。只有确认选择后才增加次数，展示选项不改变属性。基础配置保持不变，升级与本轮状态分开管理。

## 能量边界

每次能量变化后：新能量 = min(当前能量上限, max(0, 旧能量 − 消耗 + 获得))。

重击必须先检查能量至少为 2；不足时拒绝行动，不扣能量、不造成伤害、不推进回合、不触发敌方行动。不能借助下限截断允许透支。

防御的 +1 在当前玩家行动结算时立即加入，蓄能立即 +2，均不得溢出。蓄能核心只增加上限，不直接补充当前能量；没有自然回能规则。

## 回合与伤害结算顺序

1. 检查战斗是否仍在进行。已结束则不再接受战斗行动。
2. 每回合开始展示当前敌方意图；Boss 依据下一次将实际执行的行动编号展示普通或特殊攻击。
3. 玩家先行动；先校验合法性，再结算资源和效果。普攻、重击分别读取基础配置和对应升级加成。
4. 玩家攻击使敌人生命降至 0 或以下，立即判定胜利；不能再结算敌方攻击，Boss 行动计数不递增。
5. 敌人仍存活，执行当前意图。实际承伤 = max(0, 敌方攻击伤害 − 本次防御减伤)。只有本回合选择防御才有减伤；不产生负伤害或治疗。
6. 玩家生命降至 0 或以下，立即判定失败，结束本轮。不存在双方同时攻击或敌人死后反击。
7. 本次攻击结束清除防御；防御不跨回合、不跨战斗保留。若战斗继续，进入下一回合并重新展示意图。

生命是否在界面截断为 0 属于展示约定；规则判定统一为 <= 0，不允许借展示处理改变胜负。

## Boss 行动计数

Boss 战开始时已执行次数为 0。下一次编号 = 已执行次数 +1。编号能被 3 整除时用特殊蓄力攻击（22），否则普通攻击（12）。蓄力仅指预告的攻击类型，不另占一回合。

只在 Boss 实际执行一次敌方行动时递增；该次攻击即使被防御完全抵消，也算实际执行。若攻击导致玩家失败，该次已执行行动仍计数；失败之后不再递增。Boss 被玩家击败或战斗已经结束时，不执行攻击且不递增。特殊攻击同样受防御减伤。

## 战斗间与挑战结束

轻型 → 升级选择 → 重型 → 升级选择 → Boss → 本轮通关。前两战选择前不得进入下一战，Boss 胜利不再升级，不创建第四场。控制层仅管理阶段与门禁，伤害和升级数值仍由原引擎结算。

玩家当前剩余生命在战斗之间原样保留，不自动恢复。升级只改变其列明属性。失败后本轮结束，重新开始恢复生命 100/100、能量 2/4、升级次数全 0，敌人状态与 Boss 计数重新初始化，从轻型敌人开始。

## 已确认的跨战斗初始化

每场新战斗当前能量重置为 2，能量上限由基础 4 加核心升级次数计算。玩家当前生命与全部升级保留，不自动回血；核心只增加上限，不补充当前能量。重新开始使用 `createInitialProgress()`，恢复生命 100、升级全 0，再由 `startBattle` 初始化能量 2/4。

## 引擎状态约定

`PlayerProgress` 仅持久化生命和升级次数；当前能量不属于跨战斗进度。`BattleState` 另存能量、上限、敌人、回合、阶段和实际敌方攻击次数。回合从 1 开始，每次接受行动后加 1（含终结行动），拒绝行动完全不变。实际攻击次数对所有敌人记录，Boss 用它计算特殊意图。伤害后的生命可为负数，胜负始终按 <= 0 判定。

`getEnemyIntent` 在终局返回 null；`performAction` 返回接受结果和本次伤害/意图，或明确拒绝原因与原状态。防御只作为本次结算局部值，不写入持久状态。类型化 API 接收引擎生成的有效进度与状态，不负责反序列化或校验外部存档。传入生命 <= 0 的进度启动战斗时直接进入失败阶段。
